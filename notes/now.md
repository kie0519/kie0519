# Now

<sub>Current · Beijing</sub>

我目前关注的不是如何再制造一个 Agent Demo，而是如何让 Agent 在更长的时间里保持方向、边界与责任。

## 上下文不是仓库

上下文是一种持续发生的取舍。系统需要知道何时检索，何时压缩，何时保留不确定性，也需要知道哪些信息不应被带入下一次判断。

更大的窗口不等于更清晰的认知。重要的是，让模型在正确的时刻看见正确的东西。

## 能力也是边界

工具让模型从语言进入行动，同时也扩大了错误的半径。

MCP、Agent Skills 与 A2A 让能力更容易组合；真正困难的部分随之转向授权、隔离、恢复与人的介入。一个成熟的 Agent 系统，不只知道怎样行动，也知道何时不该行动。

## 评测定义产品

Evals 并不是开发完成后的考试，而是业务判断的可执行形式。

如果无法说明什么叫完成、什么叫失败、什么错误不可接受，那么产品仍然没有被定义。可靠性不是模型单独提供的属性，而是整个系统共同维持的结果。

## 界面正在成为行动

Agentic Coding 与 Computer Use 正在改变软件的入口。人不再逐步操作每一个界面，而是表达目标、观察过程，并在关键节点作出判断。

值得设计的不只是更自然的对话，而是更清楚的人机责任关系。
